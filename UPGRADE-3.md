# Обновление до 3.0.0

Сохранены все прежние инструменты и права OAuth. Изменения .env выполняйте дополнением, не заменяйте действующие пароли и токены примером.

1. Сделайте закрытую резервную копию исходников, .env и docker-compose.yml; сохраните предыдущий Docker image под отдельным тегом. .env не добавляйте в Git или публичный архив.
2. Добавьте `mail_tools.py`, обновите остальные исходники и requirements.txt. В image установлен `pypdf==6.21.0`.
3. Добавьте постоянный volume `/data` для каталога IMAP-тегов. В Dockerfile каталог принадлежит UID/GID 10001. Новый named volume инициализируется из образа; существующий bind mount требует соответствующих прав. Корень контейнера остаётся read-only.
4. Сохраните прежние `OAUTH_ISSUER`, `OAUTH_CLIENT_ID`, `MCP_PUBLIC_URL`, allowlists и секреты. Если прежняя персональная версия имела адреса в коде, перенесите их в env перед запуском переносимой версии.
5. При внутреннем прокси на другом порту укажите `OAUTH_BACKCHANNEL_URL=https://auth.example.com:18443/application/o/yandex-mail-mcp/`. Имя хоста и путь должны совпадать с issuer; внешний issuer/audience не меняются, проверка TLS не отключается. Заголовок Host остаётся каноническим. Сначала проверяется канонический HTTPS JWKS; при сетевом сбое — настроенный backchannel. Переключение локального прокси между 443 и 18443 покрывается обоими маршрутами, если они настроены для того же хоста.
6. Соберите image и сначала запустите изолированный экземпляр на loopback-порту. Выполните `python oauth_check.py` и `python smoke_test.py --imap`. Health сам по себе не проверяет OAuth или IMAP.
7. Проверьте новые записи только на отдельной копии письма в отдельной папке. Проверяйте чтением фактических флагов и содержимого целевой папки.
8. Обновите основной контейнер, сохраните env, порты и маршруты. Повторите OAuth/IMAP и клиентскую проверку. Обновите список инструментов в клиенте, если он кеширует tools/list.

## Откат

Верните предыдущий image, исходники, compose и закрытую резервную копию .env. Не удаляйте named volume `/data`: он содержит только каталог тегов, но нужен для сопоставления названий с IMAP keywords. Откат сервиса не отменяет уже выполненные операции с письмами. Тестовые папки/копии не удаляются автоматически.

## Проверенные ограничения

Цветные метки веб-интерфейса Яндекса и серверные правила сортировки не реализованы через неофициальные закрытые API. Инструменты меток возвращают `backend=imap_keywords` и `native_web_labels=false`. SMTP, delete, EXPUNGE и удаление папок отсутствуют.
