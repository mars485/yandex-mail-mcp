# Проверки версии 3.0.0 — 16 октября 2026

## Автоматические проверки

- `pytest -q`: **72 passed** на Python 3.12 / Windows.
- `pip check`: конфликтов зависимостей нет.
- MCP публикует **48 инструментов**, из них 26 чтения и 22 записи. Прежние шесть имён сохранены.
- Все 22 инструмента записи проверены с read-only токеном: отказ до IMAP-вызова.
- Проверены stale UIDVALIDITY, отсутствующие UID, размеры пакетов, сохранение остальных флагов, запрет Deleted/Draft/Recent и произвольных флагов через общий setter, Корзина и её подпапки, отсутствие DELETE/EXPUNGE fallback.
- Проверены точность base64-фрагментов и SHA-256 вложения, лимиты до загрузки MIME, текстовые вложения, отказ для зашифрованного PDF, отсутствие сохранения по недоверенному имени вложения.
- Проверены сохранение каталога IMAP-тегов между экземплярами, идемпотентное создание, стабильный keyword при переименовании и native_web_labels=false.
- Проверены structured search, отказы для инъекций/неверных типов и ограниченный fallback при ошибке HEADER Message-ID.
- Сохранены проверки OAuth RS256, issuer/audience/client, подписи, ID token, scopes и кеша. Проверено переключение canonical JWKS на фиксированный HTTPS-backchannel при сетевой ошибке без отключения TLS.

Тесты используют фиктивный IMAP и временные RSA-ключи, без реальных секретов.

## Живая установка

- Docker image сначала проверен на изолированном loopback-экземпляре, затем на основном сервисе.
- Основной сервис: OAuth discovery, PKCE, mail scopes/offline_access, RSA JWKS, unauthorized 401, MCP initialize, tools/list=48 и IMAP list_folders — успешно.
- Публичный health: HTTP 200. Вызов list_folders из подключённого чата после обновления успешен.
- Полный успешный прогон изолированного сервиса проверил **41 различный инструмент**. Предыдущий прогон дополнительно успешно выполнил copy_message и rename_folder: совместно **43 различных инструмента**. Не заявляется выполнение всех 48 операций на живом ящике.
- Успешны STATUS, namespace, subscriptions, поиск, заголовки/BODYSTRUCTURE, EML-фрагмент, пакетное чтение, связи переписки, статистика отправителей и кандидаты в дубли.
- На существующем PDF проверены список вложений, фрагмент байтов и извлечение текста; содержимое и реквизиты в протокол проверки не включены.
- На отдельной копии рекламного письма проверены Seen/Flagged/Answered/$Forwarded, пакетные флаги, IMAP-теги, FLAGS/KEYWORD search, снятие тегов, COPY и MOVE. Исходник на месте, постоянные флаги сохранены. Сессионный Recent исключён из сравнения.
- Тестовые папки и одна копия письма сохранены: удаления не выполнялись.
- Во время проверки HTTPS-прокси переключился с 18443 на 443. Canonical/backchannel-проверка покрывает оба настроенных HTTPS-маршрута, сохраняя issuer, Host и TLS.

## Ограничения

- В проверенном CAPABILITY нет QUOTA, SORT, THREAD, IDLE и X-GM-LABELS; эти функции не заявлены.
- HEADER Message-ID возвращал backend error; fallback явно помечает неполноту. Отрицательный результат не доказывает отсутствия письма во всём ящике.
- Цветные веб-метки Яндекса и серверные правила не реализованы. Категории MCP — IMAP keywords + постоянный каталог SQLite.
- MIME до 8 MiB; вложения порциями до 256 KiB; извлечение PDF/text до 2 MiB и 100 страниц, без OCR и паролей.
- Сетевой сбой записи может означать частичный или неизвестный результат. Повтор только после проверки фактического состояния.
- Это функциональная проверка, не независимый аудит безопасности и не гарантия будущих изменений сети/Яндекса.
